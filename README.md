# 个人部署首页

一个自部署的个人导航首页，形态参考 [mtab](https://github.com/tsxcw/mtab)：打开浏览器就是你的图标桌面，图标、分组、壁纸、笔记全部在你自己手里。

**后端零依赖**（Node 内置 `node:sqlite` + 打包成单文件），**数据库是单个 SQLite 文件**，**笔记是真实的 `.md` 文件夹**。

| **文字自动适配壁纸** | 压在壁纸上的文字读取壁纸对应位置的实际明暗来选黑或白，每一处各自判断；也可手动固定 |

| **Chrome 密码管理器** | 本机加密保险库、按网站提示与填充、密码生成、密文备份及本站账号同步；0.3.0 更新界面、四语切换、首次介绍和服务器连接表单记忆，见 [插件使用说明](chrome_plug_in/README.md) |
| **Clash 订阅中心** | 按 URL 统一拉取多个订阅，分别记录备注、流量和到期倒计时；服务端定时更新，按筛选、命名、去重和分流规则生成 Clash / Mihomo YAML、通用链接及 Base64 订阅 |

## 快速开始

### 方式一：Docker Compose（推荐）

```bash
git clone <你的仓库地址> home-dashboard
cd home-dashboard
docker compose up -d
```

然后打开 `http://服务器IP:9200`。

```bash
docker compose logs -f      # 看日志（首次启动会打印初始账号）
docker compose down         # 停止（数据保留在 ./data）
docker compose up -d --build  # 改了代码后重新构建
```

### 方式二：宿主机裸跑

需要 **Node.js ≥ 22.5**（内置 `node:sqlite` 是这个版本才有的）。

```bash
# Linux / macOS
./scripts/start.sh

# Windows
scripts\start.bat
```

首次运行会自动装依赖并构建。只想重启、不想重新构建：

```bash
SKIP_BUILD=1 ./scripts/start.sh
```

> **小技巧**：后端会被打包成单个文件 `app/server/dist/bundle.mjs`（运行时不需要额外安装依赖）。
> 构建一次之后，你只需要把 `app/server/dist/bundle.mjs` 和 `app/web/dist/` 两个东西拷到服务器上，
> 加一句 `node app/server/dist/bundle.mjs` 就能跑，**服务器上连 `node_modules` 都不用有**。

### 方式三：本地开发

```bash
pnpm install
pnpm dev
```

前端 `http://localhost:5173`，后端 `http://localhost:9200`，Vite 已经把 `/api` 代理到后端，改代码前后端都会热重载。

## 首次登录

首次启动会自动创建管理员账号并写入数据库：

| | |
|---|---|
| 用户名 | `admin`（可用 `ADMIN_USERNAME` 改） |
| 密码 | `admin123`（可用 `ADMIN_PASSWORD` 改） |

**登录后请立刻在「设置 → 账号与安全」里改掉密码。** 改密码会把所有设备的会话全部下线，这是刻意的。

同一账号可以在电脑、手机和 Chrome 扩展同时登录。「设置 → 账号与安全 → 登录设备」显示设备、登录 IP、登录时间和最近活动，可以单独退出一台设备，或保留当前设备并退出其它设备。设备名称由浏览器信息识别，同一设备使用不同浏览器会分别显示。

升级会保留有效的旧登录 Cookie。网页会话默认保持 30 天，支持刷新续期；刷新凭据按设备轮换，短时间并发重试返回相同后继凭据，异常重放只撤销对应设备。Chrome 扩展 0.3.1 使用独立的 2 小时会话，不读取或修改网页 Cookie。

> 默认管理员账号**只在数据库首次初始化时创建**。改了 `.env` 里的账号密码再重启是无效的，
> 因为数据库里已经有用户了。

## 数据放在哪

所有数据都在一个目录里，默认 `app/server/data/`，Docker 下是 `/data`（挂载到 `./data`）：

```
data/
├── app.db            # SQLite 数据库（图标、分组、设置、账号、探针节点）
├── app.db-wal        # WAL 日志（运行时有，正常关闭后会自动合并）
├── uploads/          # 你上传的图标和壁纸
├── notes/            # 笔记（纯 .md 文件，默认位置）
└── favicon-cache/    # 抓取过的网站图标缓存，删掉会自动重建
```

**备份 = 复制这个目录。** 或者用 `scripts/backup.mjs`（见[备份与恢复](#备份与恢复)）。

## 笔记模块

笔记**不是存在数据库里的**，就是一个装满 `.md` 文件的真实文件夹。

默认位置 `data/notes/`，可以用 `NOTES_DIR` 指向任何路径：

```bash
NOTES_DIR=/volume1/homes/me/notes    # 群晖同步盘
NOTES_DIR=D:\OneDrive\我的笔记        # Windows 同步盘
```

这么做的好处：

- **你现有的网盘同步就等于笔记多端同步** —— 不需要这个项目做任何同步逻辑
- 可以用 VS Code / Typora / Obsidian 直接编辑，改完页面刷新就能看到
- 数据永远是你的，不依赖这个项目也能读

代价是**你要为冲突负责**，所以前端做了保护：保存时会带上读文件时拿到的 `mtime`，
如果发现磁盘上的文件被外部改过，**不会静默覆盖**，而是弹窗让你选「用我的版本覆盖」还是「放弃修改、加载磁盘版本」。

安全上，所有路径都做了规范化和越界校验，`../` 之类的目录穿越、符号链接逃逸、NTFS 数据流都会被拒绝。

### 整理目录

目录树直接拖：

- 拖到**文件夹**上 → 移进这个文件夹
- 拖到**文件**上 → 移进这个文件所在的目录（同级）
- 拖到下面的**空白处** → 移到根目录

拖动时跟着光标的小标签会写着「文件名 → 目标目录」，落点行会高亮。移动只改路径、
不动内容，所以**正在编辑的文件被搬走也不会丢改动**（打开着的文件路径会跟着走）。
拖到无效的地方（比如把目录拖进它自己的子目录）不会发生任何事，也不会把它丢到别处。

移动端在目录抽屉里**长按**一下就能拖（短滑仍然是滚动列表）。键盘用户走行尾的
「重命名 / 移动」按钮，可以直接填目标路径。

> 刻意**没有做拖拽排序**：笔记树的顺序是按名字算的（目录在前、文件在后、数字感知），
> 没有可以持久化的顺序字段 —— 拖出来的顺序存不住，不如不做。要调顺序就改名
> （例如加 `01-` 前缀）。
>
> 重名不会被覆盖：目标已存在时后端直接拒绝并提示，不会静默替换掉同名笔记。

## 服务器面板

顶部工具栏的仪表图标进入（`/servers`）。把「本机」和你配过的所有探针节点放在一屏里，
每 5 秒自动刷新一次。

每台服务器展示：

- **CPU** 使用率（两次采样之间的平均值）、型号、核心数
- **内存** 已用 / 总量；Linux 上还有交换分区
- **磁盘** 第一个挂载点的占用，展开可看全部（最多 5 块）
- **负载** 1 / 5 / 15 分钟
- **网速** 上行 / 下行（Linux）
- **地址** 公网 IP 与内网 IP
- 主机名、系统与内核、架构、运行时长

进度条颜色：`< 70%` 绿 · `70–89%` 琥珀 · `≥ 90%` 红。

### 标签与备注

**每一台都能编辑**，包括「本机」——卡片右上角的铅笔图标进去改。

- **标签**：每台最多 10 个、每个 24 字以内。中英文逗号都能分隔（`生产，海外` 和 `prod,oversea` 都认），
  自动去空白、忽略大小写去重。打完会在卡片上显示成小块，页面顶部出现**筛选行**，
  点一下只看带这个标签的机器。
- **备注**：最多 500 字，比如「跑数据库，2026-03 到期，续费走公司卡」。
  卡片上最多显示两行，悬浮可以看到全文。

编辑框里会列出**你已经用过的标签**，点一下就能加上，不用每次手打。

> 「本机」在节点表里没有记录（它就是主服务自己），所以它的备注和标签存在设置里，
> 名字也是固定的。

### 管理面板入口

每台机器都能记一份**面板地址、账号、密码、备注**（宝塔之类），存在编辑弹窗的
「管理面板」分组里。

- 填了地址，卡片右上角会出现一个 **↗ 入口按钮**，点一下直接开面板
- 展开详情能看到完整凭据，每项都有**复制**按钮，密码默认**打码**、点眼睛才显示
- **离线也能看** —— 服务器挂了正是最需要翻面板密码的时候

> ⚠️ 密码是**明文存在你自己的 SQLite 里**的（和 `agent_token` / `jwt_secret` 一样）。
> 这个库本来就在你自己机器上，但**导出数据（设置页的「数据备份」）会把它一起带出去**，
> 别随手发人。

### 「本机」是怎么来的

主服务自己就跑在一台机器上，所以这台**直接用进程内的 `os` + `fs` 采集，不走探针**，
省掉一个探针端口。它的输出和探针的**完全同构**，前端不需要为它写第二套逻辑。

> 两处是独立实现（探针必须保持零依赖单文件，不能 import 主程序的 TS），
> 改采集口径时要同步改两边 —— `app/server/src/lib/sysinfo.ts` 和 `agent/node/index.mjs`。

### 想看别的服务器

在那台机器上跑起探针（见 [agent/README.md](agent/README.md)），
再到「服务对接」里把它加为节点即可，面板会自动带上它。

### 几个已知口径

| | |
|---|---|
| 负载 | **Windows 上显示 `—`** —— `os.loadavg()` 在 Windows 恒返回 0，那是「不支持」不是「没负载」，给假数字不如不给 |
| 网速 | **只有 Linux 有**，读 `/proc/net/dev` |
| 交换分区 | 只有 Linux 有 |
| CPU 首次采样 | 探针会等 200ms 再采第二次，所以第一个请求就有真值，不用等一个刷新周期 |
| 探测超时 | 单台探针 4 秒；某台掉线不影响其它台 |
| 缓存 | 服务端缓存 3 秒，多开页面不会把每台探针打成轮询靶子 |
| 容器里的内存总量 | 显示的是**宿主机**的内存，不是容器的 cgroup 限制。Node 的 `os.totalmem()` 拿不到 cgroup 配额，所以给容器设了 `mem_limit` 的话这个数会偏大 |

## 内置主题

在「设置 → 外观 → 内置主题」选择经典玻璃、云端桌面、简约留白、奶油手账或深空终端，点击「应用主题」保存。云端桌面在电脑上提供应用窗口与底部 Dock，手机仍保留四列导航；其它主题分别提供简洁线条、暖色纸感和等宽终端风格，每套都支持深浅色。

默认勾选「保留现有壁纸」，图片、视频和两套壁纸的模糊/压暗配置不会被覆盖；取消勾选会同时应用推荐壁纸。当前设置页内可「恢复上一次外观」。应用后仍可继续调整壁纸、卡片大小等选项。

整套外观会保存到服务器并随备份导入导出，深浅色选择继续只保存在当前设备。升级默认沿用经典玻璃和已有配置。

## 壁纸：浅色一套、深色一套

「跟随系统 / 浅色 / 深色」仅保存在当前浏览器，手机切换不会让电脑一起切换；设置入口保留，刷新、重新登录和导入备份不会覆盖本机选择。壁纸、卡片等其它外观配置仍按原方式同步。

壁纸（以及纯色底）**按主题分两套**：浅色主题用一套、深色主题用一套，切主题时自动换。

设置 → 外观 → 「正在编辑哪套壁纸」里选浅色还是深色，下面就是那套的类型 / 预设 / 上传。
**改完自动保存**，不用点确定。

主题设成「跟随系统」时，系统切深浅色，壁纸也跟着换 —— 两套都配好就行。

> 升级上来的老实例：原来那张壁纸会被**同时复制给两套**，所以升级完不管当前
> 是深是浅，看到的还是原来那张，不会突然变样。

想给浅色配纯白、深色配纯黑：两套都选「纯色」再挑 `#ffffff` / `#000000` 即可。

动态壁纸：在「壁纸类型」选择「动态壁纸」，上传 MP4 / WebM（默认最大 100MB），或填写视频直链后点「应用链接」。推荐 MP4 H.264 或 WebM VP9；视频平台页面链接不是视频直链。浅色、深色可以分别设置视频，上传文件随数据目录一起备份。

视频静音循环播放，右下角可以暂停或继续；页面进入后台、预览滚出视口时暂停，系统开启「减少动态效果」时默认暂停。播放失败会退回渐变背景，设置预览会显示错误提示。动态视频至少压暗 55% 并使用稳定的白色文字，避免画面变化时文字闪跳；已有文字颜色手动配置仍有效。

服务端可通过 `MAX_VIDEO_UPLOAD_MB` 调整视频上限；Nginx 的 `client_max_body_size` 应略大于文件上限以容纳表单开销，例如默认 100MB 视频使用 `110m`。上传视频仅校验容器与视频轨，不做转码，播放能力取决于浏览器支持的编码。

## 壁纸上的文字颜色

首页时钟区、分组标题、子页面标题这三处文字是**直接压在壁纸上**的，没有卡片托底。
默认情况下它们会**自动**选黑或白 —— 读取壁纸在那一块的实际明暗来决定，
不是拍脑袋跟着主题走。

壁纸「上半亮、下半暗」很常见（天空 + 地面就是），所以每一处是**各自判断**的：
时钟按它所在的那块算、分组标题按它所在的那块算。同一屏里出现黑字和白字是正常的。

设置 → 外观 → **壁纸上的文字颜色**里可以把任意一处固定成黑或白：

| 选项 | 行为 |
|---|---|
| 自动 | 读壁纸对应位置的明暗（默认） |
| 黑 | 不管壁纸，一律深色字 |
| 白 | 不管壁纸，一律白色字 |

> 什么时候需要固定：壁纸在某处恰好是中间调（黑字白字对比度都不够）时，
> 自动判定会来回摇摆。这时手动钉死一个反而更稳。

## 小组件（天气 / 一言）

两个都靠外部接口，但**请求路径上永远不等它们** —— 数据在服务端提前备好，
接口响应是毫秒级的。

### 天气

服务端缓存 **3 小时**，落盘保存（重启不丢）：

- 缓存新鲜 → 直接返回，零外部请求
- 缓存过期 → **先返回旧值**，同时在后台去刷新（所以刷新永远不会卡住你）
- 完全没有 → 才等这一次（首次启动会主动预热，所以其实也等不到）

**两个天气源可选**（设置 → 小组件 → 天气源）：

| 源 | 实测延迟 | 覆盖 | 需要 Key |
|---|---|---|---|
| **国内（中国天气网）** ← 默认 | **19–70ms** | 内置 359 个中国城市 | 否 |
| 国外（open-meteo） | ~880ms | 全球任意城市 | 否 |

国内源走 `d1.weather.com.cn`：免 Key、国内直连、比国外源快十几倍。
**内置表里没有的城市会自动落到国外源**，所以填生僻地名也不会报错。

> 为什么加国内源：open-meteo 要绕到德国（实测 877ms），而且它的 geocoding 主机
> `geocoding-api.open-meteo.com` **从国内根本连不上** —— TCP 能连、TLS 握手被丢，
> Node 报 ETIMEDOUT（curl 因为 TLS 指纹不同反而能通）。表现就是「本地天气好好的、
> 线上一直失败」。国内源从根上绕开了这个问题。

**城市码表是生成的，不是手写的。** 中国天气网认的是城市码（`101210401` = 宁波），
而这份编号没有公开规律，凭记忆写必然错几个 —— 错了就是「查宁波返回深圳的天气」，
而且很难发现。所以直接对着接口枚举了 359 个城市，每个码都用返回的 `cityname` 校验过。
详见 `app/server/src/lib/city-codes.ts` 顶部的说明。

### 每日一言

服务端**后台预取一池子**（12 条，落盘），请求直接从池子里轮着拿：
零延迟，而且每次刷新页面会换一句。

> 接口前面挂着 Cloudflare，同一个 URL 会被缓存成同一句 —— 所以每次取都带一个随机参数，
> 否则并发取 6 条会拿到 6 条**一模一样**的，池子白建。

### ⚠️ 宝塔用户注意：全局 proxy_cache

宝塔的 nginx 里有一行全局的 `proxy_cache cache_one;`（在 `/www/server/nginx/conf/proxy.conf`），
**它会缓存所有带可缓存头的代理响应**。

所以这两个接口**必须发 `Cache-Control: no-store`**。早先它们发的是 `public, max-age=...`，
结果被 nginx 缓存住，一言的「每次换一句」直接失效 —— 而且是那种最难查的症状：
直连应用端口一切正常，走域名就永远是同一句。

排查时看这两点：

```bash
# 应用本身发的是什么头
curl -sI -H "Authorization: Bearer <token>" http://127.0.0.1:9200/api/widgets/hitokoto | grep -i cache

# nginx 那边缓存了哪些东西
find /www/server/nginx/proxy_cache_dir -type f | wc -l
```

改完记得把旧缓存清掉：`rm -rf /www/server/nginx/proxy_cache_dir/*`

（派生图和 favicon 确实该缓存，它们保留 `public, max-age=...` 是对的。）

## 工作台

首页小组件「工作台 →」进入（设置 → 小组件里可以关掉这个入口）。

放的是**要登的后台和系统**：每条记名称、分组、网址、**用途**、账号、密码、备注。

- **左侧分组栏**：全部 / 各个分组，带条数。桌面端 sticky 跟随，移动端变成一条可横向滑动的分组条
- **卡片平铺凭据**：账号直接显示、**密码默认打码**，点眼睛才展开；每项都有复制按钮
- **按分组分区展示**，每组右上角有个「加一条」，新条目自动落在这个分组里
- **搜索**：条目超过 4 条时才出现。搜名称 / 用途 / 网址 / 账号 / 备注 ——
  **但故意不搜密码**：拿密码去搜等于把明文扩散到更多地方，也没人会这么找

### 和首页图标墙的区别

| | 首页图标墙 | 工作台 |
|---|---|---|
| 面向 | 「点开就走」的常用站点 | 「打开 → 看用途 → 复制账号 → 复制密码」 |
| 一条有什么 | 名字 + 地址 + 图标 | 名字 + 分组 + 网址 + 用途 + 账号 + 密码 + 备注 |
| 在首页？ | 是 | 不是，只有一颗入口 |

所以是**单独一张表**，不是给 `sites` 加几列 —— 混在一起会让首页那套卡片逻辑处处要判空。

> ⚠️ 密码是**明文存在你自己的 SQLite 里**的（和 `agent_token`、宝塔凭据一样）。
> 界面默认打码，**整个接口都要登录**（匿名拿是 401），
> 但**导出数据会把它带出去**，别把备份随手发人。
> 另外搜索刻意不覆盖密码字段。

**分组用的是字符串**，不另建一张表：这里的分组就是「云服务 / 内部系统 / 财务」这种十来个固定标签，
单独建表要多一次 join、多一套增删接口，改个名还要跨表更新。需要整组改名时接口里有对应的方法。

## 照片墙

顶部工具栏的图片图标进入。你上传过的所有图片（图标、壁纸、照片）都在这里，按上传时间倒序。

- **上传**：点「上传图片」多选，或直接把文件拖进页面（一次最多 40 张，单张最大 20MB，可用 `MAX_UPLOAD_MB` 调）
- **瀑布流**：按图片原始宽高比排布，不裁切、不变形
- **点开大图**：灯箱里可以左右方向键翻页、`Esc` 关闭，并能下载、复制直链、**一键设为壁纸**、删除
- **小图过滤**：favicon 这类只有几 KB 的小图默认不显示（否则墙上全是看不清的小点），
  右上角「显示全部」可以切回来
- **存储位置**：文件在 `data/uploads/`，数据库里只存元信息。**直接把文件拷进这个目录不会出现在墙上**
  —— 记录在数据库里，要走上传接口才会登记

> 上传时磁盘上用的是生成的随机名（避免重名和中文路径问题），但原始文件名会一并存进数据库，
> 界面上显示的是你原来的文件名。

### 图片加载优化

上传时会在**浏览器里**生成两张派生图，网格和灯箱分别用它们，不再直接拉原图：

| 用途 | 尺寸 | 实测（一张 5.7MB 的 PNG / 7.2MB 的 JPG） |
|---|---|---|
| 网格缩略图 | 最长边 480，WebP | **22–23 KB**（比原图小 99.6%） |
| 灯箱中等图 | 最长边 1600，WebP | ~350 KB |

- **网格**一律用缩略图，`loading="lazy"` + `decoding="async"`
- **灯箱分两步**：先把缩略图铺成背景占位（它已在缓存里，瞬间出现，不用对着黑屏等），
  大图加载完盖上去
- **大图按设备选**：用 `<picture>` + `media`，**手机（≤640px）拿中等图，桌面才拉原图** ——
  手机屏幕小又是流量，没必要为它下 7MB

> **为什么在浏览器生成**：服务端缩图需要 `sharp` 这类原生依赖，会打破这个项目
> 「单文件 bundle、运行时零依赖、镜像里不带 node_modules」的设计。浏览器本来就有
> 最快的解码器（`createImageBitmap` 常走硬件），顺手就用了。
> 代价：**用 API/curl 直传的图片没有派生图**，前端会自动退回原图。

**已有图片**：如果图是这个功能上线前传的，照片墙右上角会出现「补齐缩略图（N）」按钮，
点一下当场补上（取回原图 → 浏览器缩图 → 传回派生图，逐张处理）。

### 首页壁纸也走派生图

壁纸同样分两步：**先铺缩略图，大图加载完再淡入**。实测线上那张 7.2MB 的壁纸：

| | 之前 | 现在 |
|---|---|---|
| 首页为壁纸传输的字节 | 7407 KB | **228 KB**（缩略图 23 KB + 大图 182 KB） |

省下约 **33 倍**，而且原图完全不再被下载。

> 这里有个反直觉的点：一开始我把原图作为最底层兜底留在 DOM 里，想着「派生图挂了还有它」。
> 结果浏览器**会把被完全盖住的 `background-image` 也下载下来** —— 优化等于白做。
> 所以现在是「派生图能用就不挂原图那层」，靠 `<img onError>` 探测派生图是否真的存在。

顺带：壁纸明暗判定（决定压什么字色）也改用缩略图采样了，
为了判断深浅去解一张 7MB 的原图不值当。

### 移动端：壁纸不会跟着地址栏变

手机上滚动时，Safari / Chrome 的地址栏会收起、展开，**布局视口的高度跟着变**。
如果壁纸直接铺在 `position: fixed; inset: 0` 上，盒子就会随地址栏一起变高变矮，
而 `cover` 是按盒子算缩放的 —— 每滑一下图片就重新缩放一次，看起来「背景自己在动」。

做法是把内容放进一个用 **`lvh`（大视口高度）固定住**的内层「舞台」，外层只当裁剪窗口。
地址栏怎么变，舞台尺寸都不变，图片自然就不会重算。
细节见 `app/web/src/index.css` 里 `.wallpaper-stage` 的注释。

### 苹果浏览器（Safari / iOS）

| 差异 | 处理 |
|---|---|
| **Safari 编不出 WebP** | `toBlob('image/webp')` 在 Safari 上会静默回退成 PNG（比原图还大）。所以导出后检查返回的 MIME，不是 WebP 就重来一次 JPEG |
| **老 Safari 没有 `createImageBitmap`** | 退回 `<img>` + objectURL 解码。讽刺的是这条路格式支持更广 —— iOS 的 HEIC 只能这么解 |
| **EXIF 方向** | 手机竖拍的照片像素是横的，靠 EXIF 标记转正。`imageOrientation: 'from-image'` 老版本不认会抛，所以再试一次不带参数的 |
| **HEIC / HEIF** | 苹果默认拍照格式，服务端**原样存**（无损保留）。Chrome / Firefox 解不了 HEIC，所以这种图的灯箱会自动改用派生图，两边都不会看到破图 |

派生图的地址也因此做成了**与编码格式无关**：

```
/uploads/derived/<名字>.thumb          ← 前端自己推地址用（Safari 是 .jpg，Chrome 是 .webp）
/uploads/derived/<名字>.thumb.webp     ← 接口返回的确切地址
```

两种写法都接受，服务端找实际存在的文件并给出正确的 `Content-Type`。

## 公网 / 内网双链路与探针

### 它解决什么问题

你家里/公司有一堆内网服务（NAS 面板、GitLab、自建博客…），在内网用 `192.168.1.10:8080` 访问，
出门在外就得走 `nas.example.com`。每次还要手动换地址很烦。

这个项目让**同一个图标带两条地址**：

```
公网地址   https://nas.example.com
内网地址   http://192.168.1.10:8080
```

切换逻辑（三层兜底）：

1. 用内网 IP / `*.lan` / `*.local` 打开首页 → 判定为内网模式，优先走内网地址
2. 后台批量探活，内网地址不通就自动回落到公网地址
3. 卡片右上角有小徽章显示当前走的是「内网」还是「公网」，单条也可以固定成「总是内网」或「总是公网」

> 探活用 `fetch(url, { mode: 'no-cors' })`：读不到响应状态码，但**网络层不可达时 fetch 会直接失败**，
> 这正好够当存活探针用，而且完全绕开 CORS 限制。

### 探针怎么部署

探针是一个**零依赖的单文件 Node 程序**，放在任何一台你想自动发现服务的机器上：

```bash
# 从主服务的「设置 → 账号与安全」里复制探针令牌
node agent/node/index.mjs --token=你的令牌
```

启动后会打印它监听的地址。默认**只绑定内网网卡**，不监听公网。

```bash
node agent/node/index.mjs --help           # 全部参数
node agent/node/index.mjs --print-config   # 打印一份配置示例
```

> **宿主没有 Node？**（NAS、路由器这类设备）用 Docker 跑，镜像和 compose 都在
> [`agent/Dockerfile`](agent/Dockerfile) / [`agent/docker-compose.yml`](agent/docker-compose.yml)：
> `cd agent && docker compose up -d --build`，详见
> [`agent/README.md`](agent/README.md#放进-docker宿主没有-node-时用这个)。

#### 推模式：探针反过来连主程序

上面那种是**拉模式**：主程序定时去连探针。要求两者在**同一个网络**里。

主程序在公网、探针在 NAT 后面的内网时，公网那台根本没有路由进去。加一个 `--server=` 即可：

```bash
node agent/node/index.mjs --token=你的令牌 --server=https://nav.example.com --interval=10
```

探针每 10 秒把指标 POST 给主程序，主程序**自动登记**这个节点，**不需要开任何入站端口**。

| | 拉模式 | 推模式 |
|---|---|---|
| 谁发起连接 | 主程序 → 探针 | 探针 → 主程序 |
| 网络要求 | 必须互通 | 探针能出网即可，**可穿 NAT** |
| 开入站端口 | 需要 | **不需要** |
| 加节点 | 手动 | **自动** |

两种可以同时用。超过 30 秒没收到上报就判离线。

**推模式还要过一道人工审批**：探针首次启动会拿共享令牌换一把**专属密钥**，
然后在面板上以「待批准」出现 —— 你点一下「批准」，它才开始真正上报
（不用重启探针，最多 10 秒就接上）。

| | 拉模式 | 推模式 |
|---|---|---|
| 谁发起连接 | 主程序 → 探针 | 探针 → 主程序 |
| 网络要求 | 必须互通 | 探针能出网即可，**可穿 NAT** |
| 开入站端口 | 需要 | **不需要** |
| 加节点 | 手动 | 自动 + **你批准一下** |
| 认证 | 共享令牌 | **每台一把专属密钥** |

> 为什么要密钥 + 批准：共享令牌是全局的，泄露就能冒充任意节点。
> 换成每台一把密钥后冒充成本高了；而新密钥默认不生效，
> 所以**即使令牌泄露**，攻击者最多让面板上多出一条「待批准」，拿不到任何东西。
> 已批准的节点也**不能**靠共享令牌重新领密钥顶掉（服务端直接拒绝）。

详见 [`agent/README.md`](agent/README.md#15-推模式探针主动连出去)。

它提供两个接口：

| 接口 | 鉴权 | 返回 |
|---|---|---|
| `GET /api/info` | 不需要 | 主机名、内网 IP、版本（**不含任何敏感信息**，否则没法做自动发现） |
| `GET /api/services` | 需要 `X-Agent-Token` | 本机监听的端口列表 + 服务名猜测 + 存活状态 |

端口来源是**自动扫描**本机监听端口，Linux 读 `ss`、Windows 读 `netstat`、macOS 读 `lsof`，
并配有一张常见端口 → 服务名的映射表（3306 → MySQL、6379 → Redis、9200 → Elasticsearch…）。
你也可以放一个 `services.json` 手动声明，清单优先于扫描结果：

```json
{
  "services": [
    { "name": "我的博客", "port": 8080, "scheme": "http", "path": "/" },
    { "name": "NAS 面板", "port": 5001, "scheme": "https", "path": "/" }
  ]
}
```

### 首页怎么发现它

用内网地址打开首页 → 首页把当前访问的主机名报给后端 → 后端拿设置里的 `agent_ports`
（默认 `9201`，可配多个，如 `9201,9202`）去探测 → 命中就把节点存下来 → 同步服务列表到图标。

> **安全提醒**：探针会暴露「这台机器开了哪些端口」，**不要把它暴露到公网**。
> 它默认只监听内网、要求令牌、支持 IP 白名单（`AGENT_ALLOW_IPS`），请保持这些默认值。

## 反向代理与 HTTPS

公网访问**务必**套一层 HTTPS。裸 HTTP 下你的登录密码是明文传输的。

### Nginx

```nginx
server {
    listen 443 ssl http2;
    server_name nav.example.com;

    ssl_certificate     /etc/nginx/ssl/nav.example.com.pem;
    ssl_certificate_key /etc/nginx/ssl/nav.example.com.key;

    client_max_body_size 110m;  # 支持默认 100MB 动态壁纸及表单开销

    # 探针订阅任务长连接，与网页和 HTTPS 回传共用 443。
    location = /api/agent/subscriptions/ws {
        proxy_pass http://127.0.0.1:9200;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade           $http_upgrade;
        proxy_set_header Connection        "upgrade";
        proxy_read_timeout 75s;
        proxy_send_timeout 75s;
        proxy_buffering off;
    }

    location / {
        proxy_pass http://127.0.0.1:9200;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

server {
    listen 80;
    server_name nav.example.com;
    return 301 https://$host$request_uri;
}
```

WebSocket 需要显式转发 `Upgrade` 和 `Connection`，Nginx 配置说明见 [官方 WebSocket 代理文档](https://nginx.org/en/docs/http/websocket.html)。修改配置后先执行 `nginx -t`，再 reload。任务连接使用同一站点的有效 TLS 证书；探针仍不需要开放公网入站端口。

若 `AGENT_SERVER` 使用已有反向代理基路径，例如 `https://nav.example.com/nav`，需要将 `/nav/api/agent/subscriptions/ws` 映射到后端 `/api/agent/subscriptions/ws`，并对 `/nav/api/agent/subscriptions/result` 及其他探针 HTTP 接口采用相同的前缀处理。上面的例子适用于站点根路径；不要把带前缀的配置直接套用，也不要在 `AGENT_SERVER` 后手工追加 WebSocket 接口路径。

### Caddy（更省事，自动签证书）

```
nav.example.com {
    reverse_proxy 127.0.0.1:9200
}
```

### 启用 HTTPS 后记得打开这个开关

HTTPS 下要让 refresh Cookie 带上 `Secure` 标志：

```bash
COOKIE_SECURE=true
```

Docker Compose 里就是取消 `docker-compose.yml` 中 `# COOKIE_SECURE: "true"` 的注释。

## 备份与恢复

```bash
# 备份到 ./backups，保留最近 10 份
node scripts/backup.mjs
# 或者用包装脚本（Linux / macOS）：./scripts/backup.sh

# 连笔记一起备份（笔记目录在数据目录之外时需要）
node scripts/backup.mjs --with-notes

# 备份到 NAS，保留 30 份
node scripts/backup.mjs --out=/mnt/nas/homedash-backup --keep=30
```

Windows 上用 `scripts\backup.bat`。

> 为什么不直接复制 `app.db`：数据库开了 WAL 模式，正在写入时单独复制主库文件
> **会丢掉还在 WAL 里的最新事务，备份出来是坏的**。脚本用的是 SQLite 的 `VACUUM INTO`，
> 由数据库自己保证一致性快照。

**恢复**：停掉服务，把备份里的 `app.db`、`uploads/`、`notes/` 覆盖回数据目录，再启动。

加进 crontab 每天自动备份：

```cron
0 3 * * * cd /opt/home-dashboard && ./scripts/backup.sh >> backups/cron.log 2>&1
```

## 配置项

复制 `.env.example` 为 `.env` 后修改。**所有项都有合理默认值，完全可以不配。**

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | `9200` | 监听端口 |
| `HOST` | `0.0.0.0` | 监听地址。只给本机反代可以改 `127.0.0.1` |
| `DATA_DIR` | `app/server/data` | 数据目录（数据库、上传、favicon 缓存） |
| `NOTES_DIR` | `<DATA_DIR>/notes` | 笔记目录，可以指向同步盘 |
| `JWT_SECRET` | 自动生成 | 留空则首次启动随机生成并存进数据库 |
| `AGENT_TOKEN` | 自动生成 | 探针令牌，可在设置页查看和轮换 |
| `ADMIN_USERNAME` | `admin` | 初始管理员用户名（**仅首次初始化生效**） |
| `ADMIN_PASSWORD` | `admin123` | 初始密码（**仅首次初始化生效**） |
| `PUBLIC_VIEW` | `false` | 允许未登录浏览首页（编辑始终需要登录）。默认关，想公开分享导航页时打开 |
| `COOKIE_SECURE` | `false` | 用 HTTPS 时设为 `true` |
| `REFRESH_DAYS` | `30` | 登录状态保持天数 |
| `DEBUG_DB` | - | 设为 `1` 时启动会打印数据库文件路径 |
| `MAX_UPLOAD_MB` | `20` | 单个上传文件的大小上限（MB） |

## 常见问题

**Q：端口被占用 / 想换端口**
Docker：改 `docker-compose.yml` 里 `ports` 的左边（如 `"8080:9200"`）。
裸跑：`PORT=8080 ./scripts/start.sh`。

**Q：忘记密码了**
停掉服务，删掉数据库文件里的用户记录即可重新初始化（会丢失账号，但图标和分组还在）：

```bash
node -e "const {DatabaseSync}=require('node:sqlite');const db=new DatabaseSync('app/server/data/app.db');db.exec('DELETE FROM users');db.close()"
```
然后重启，会用 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 重新创建管理员。

**Q：图标全是首字母，抓不到网站图标**
favicon 抓取要服务器能访问外网。纯内网环境抓不到是正常的，可以在编辑图标时手动上传，
或者手动填图标 URL。抓取失败的域名会负缓存 6 小时，成功后缓存 14 天。

**Q：笔记目录放进网盘后变慢**
目录树是纯 `readdir`，不会读文件内容，所以正常不会慢。但如果网盘的「按需下载」把文件变成了占位符，
遍历可能触发水合。这种情况下建议把 `NOTES_DIR` 指向本地目录，用网盘客户端之外的方式同步。

**Q：怎么让新标签页直接打开这个首页**
可以在浏览器的启动设置里指定导航站地址。Chrome 自定义新标签页还需要支持替换新标签页的扩展；本项目的 Chrome 插件是密码管理器，不替换新标签页。

**Q：Docker 容器里要连宿主机的数据库或者服务**
容器内的 `127.0.0.1` 不指向宿主机。Linux 上用 `--network host` 或宿主机的 docker 网桥 IP。

## 开发

```bash
pnpm dev            # 前后端一起起
pnpm dev:server     # 只起后端
pnpm dev:web        # 只起前端
pnpm typecheck      # 双端类型检查
pnpm build          # 生产构建（前端 dist + 后端单文件 bundle）
pnpm test           # 主站请求、插件、服务器同步回归测试（使用隔离数据）
pnpm test:extension # 扩展、四语文案、表单缓存与服务器密文接口回归
pnpm pack:extension # 生成 chrome_plug_in-0.3.1.zip（先检查扩展语法和页面资源）
pnpm test:browser   # 可选：真实浏览器扩展回归，环境配置见 chrome_plug_in/README.md
```

技术栈：

- **前端** Vite + React 19 + TypeScript + Tailwind CSS v4 + zustand + dnd-kit + CodeMirror 6
- **后端** Node 24 + Hono + 内置 `node:sqlite`（**零原生依赖，不需要编译**）
- **认证** scrypt 密码哈希 + JWT access token（2h，只存内存）+ 轮换 refresh token（30d，HttpOnly Cookie）

> 用 `node:sqlite` 而不是 `better-sqlite3` 是刻意的：省掉原生模块编译，
> Windows 和 Alpine 容器里行为完全一致，部署时不会卡在 build tools 上。
> 数据库访问都收在 `app/server/src/lib/db.ts` 一个文件里，将来想换实现只改那一处。
